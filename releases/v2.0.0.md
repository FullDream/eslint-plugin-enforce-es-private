# 2.0.0 — safer native private member migration

This major release focuses the plugin on TypeScript `private` → ECMAScript
`#private`, fixes unsafe renaming, and supports ESLint 8.57, 9 and 10.

## ⚠️ Breaking changes

-   **Presets enable independent member rules.** Set severity on `fields`,
    `methods`, `getters`, `setters` and `auto-accessors` separately. The aggregate
    `typescript-private` rule is disabled in recommended presets but remains
    available for manual configurations. Update any preset overrides accordingly.
-   **`configs.recommended` is now an object.** Use
    `[enforceEsPrivate.configs.recommended]` instead of spreading an array or
    indexing `[0]`. The preset includes the TypeScript parser and targets
    `.ts`, `.tsx`, `.mts` and `.cts`. Use `recommended-type-checked` for a ready-to-use
    preset with Project Service and safe autofix.
-   **`underscore-prefix` has been removed.** Remove
    `enforce-es-private/underscore-prefix` from your ESLint configuration. All
    recommended configurations now enable the independent member rules.
-   **Autofix requires type information.** Enable
    `parserOptions.projectService: true` (or `project: true`), or select
    `configs['recommended-type-checked']`.
    Without type information, the rule reports without changing code.
-   **Names are preserved.** `private _field` becomes `#_field`, not `#field`.
-   **Node.js minimum:** `^18.18.0 || ^20.9.0 || >=21.1.0`. With ESLint 10, use
    `^20.19.0 || ^22.13.0 || >=24` and typescript-eslint 8.57.2 or newer.

## Migration to the new flat presets

```js
import enforceEsPrivate from 'eslint-plugin-enforce-es-private'

// Diagnostics without a TypeScript project:
export default [enforceEsPrivate.configs.recommended]

// Or, in a project with tsconfig.json, diagnostics and safe autofix:
// export default [enforceEsPrivate.configs['recommended-type-checked']]
```

Remove `...` when inserting the recommended preset into an array. Replace
`configs.recommended[0]` with `configs.recommended` when customizing the config
through object spread. `legacy-recommended` retains its existing shape.

## Migration from underscore-prefix

Use the standard `@typescript-eslint/naming-convention` rule to forbid leading
underscores on class members:

```js
'@typescript-eslint/naming-convention': ['error', {
  selector: ['classProperty', 'classMethod', 'classicAccessor'],
  format: null,
  leadingUnderscore: 'forbid',
}]
```

Register `@typescript-eslint/eslint-plugin` first. ESLint core's
`no-underscore-dangle` with `enforceInClassFields: true` and
`enforceInMethodNames: true` is another option with a broader scope.
These rules enforce naming; they do not convert underscore members to runtime
private members. To opt into conversion, declare members `private` explicitly.

## Fixes and improvements

-   Configure `error`, `warn` or `off` independently for fields, methods, getters,
    setters and auto-accessors using the member rules. The aggregate rule's
    `members` option remains available for configurations with a shared severity.
-   Private constructors and constructor parameter properties are ignored; they
    cannot be directly converted to native private declarations.
-   Symbol-aware fixes preserve unrelated variables, properties and nested classes.
-   Bracket access such as `instance['field']` now blocks conversion instead of
    leaving broken string access behind.
-   Dynamic keys, external references, ambiguous receivers, reflection,
    destructuring and other unsupported cases report without unsafe edits.
-   Correct method diagnostics, CommonJS type exports and clean npm builds.
-   Regression tests and CI coverage for supported ESLint generations.

See [the migration guide](https://github.com/FullDream/eslint-plugin-enforce-es-private#migrating-from-v1-underscore-prefix-removed)
and [full changelog](https://github.com/FullDream/eslint-plugin-enforce-es-private/blob/main/CHANGELOG.md).
